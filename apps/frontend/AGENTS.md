# Frontend (Next.js App Router)

The block above is managed by Next.js. Our own rules follow; read `../../AGENTS.md` first.

## Structure

| Folder | Holds |
| --- | --- |
| `src/app/` | Routes only. Each `page.tsx` / `layout.tsx` re-exports a component (`export { default } from "@/components/pages/Clients"`) plus its `metadata` |
| `src/components/layouts/` | App shells (`RootLayout`) |
| `src/components/providers/` | Context providers (`AppProvider` composes them) |
| `src/components/forms/` | Forms: they only draw fields; state lives in a form hook (`useTimeEntryForm`), saving in the panel |
| `src/components/shared/` | Reusable UI (table, pagination, side panel, form controls, …) and `TimeEntryPanel`, used by both pages |
| `src/components/pages/` | One folder per screen; screen-only parts live in sub-folders of it |
| `src/components/styled/` | Typography: `Heading1`, `Heading2`, `Paragraph`, `Span` |
| `src/hooks/` | UI hooks; `src/hooks/queries/` for data hooks (TanStack Query) |
| `src/generated/api/` | API client generated by Hey API from `../backend/openapi.json`. **Never edit**; run `npm run api:generate` |
| `src/services/` | `apiClient.ts` (turns every error into `ApiRequestError`); `catalog.ts` and `timeEntries.ts` wrap the generated API functions, including the idempotent delete |
| `src/constants/` | App-wide values, validation messages |
| `src/models/` | What the data **is** (`Client`, `TimeEntry`, …), re-exported from the generated types |
| `src/interfaces/` | How data **travels or is used** (request params, props, form values) |
| `src/assets/icons/` | SVG icons (24×24, `stroke="currentColor"`), exported as components from `components/shared/Icons` |
| `src/utils/` | Pure functions (dates, errors, form validation, URL params); unit-tested |
| `src/styles/` | `_colors.scss`, `_typography.scss`, `_layout.scss` tokens, `global.scss` resets |

## Conventions

- **Every component is a folder** with `index.tsx` and `styles.module.scss`.
- **`"use client"` only where server code hands over:** the page components in `components/pages/<Name>/index.tsx`,
  the providers and the sidebar. Components and hooks they import are client code already; don't mark them.
- **Styling:** SCSS modules only. Use the token functions (`color()`, `background()`, `border-color()`,
  `font-size()`, `font-weight()`, `space()`, `radius()`) and the layout mixins. No hard-coded colours,
  no inline `style={…}`. An unknown token name fails the build on purpose.
- **Text** goes through the styled components (`<Heading1>`, `<Paragraph>`, `<Span>`), not raw tags with classes.
- **Form fields** use the shared `Dropdown`, `DateTimeInput` and `TextArea` (label and error built in, native elements underneath). No form library.
- **Buttons:** `variant` is `primary`, `secondary` or `tertiary` by importance, `danger` for destructive actions.
- **Data flow:** components → `hooks/queries` → `services/` → generated client → `/api`. Components never call `fetch`.
  A service wraps one generated function (passes `signal`, sets `throwOnError: true`, returns the data). A hook
  uses it as `queryFn` / `mutationFn` and adds only what's ours (`staleTime`, `placeholderData`, `select`,
  `enabled`). Query keys come from the generated `*QueryKey()` functions; after a write, invalidate
  `listTimeEntriesQueryKey()` (without options it matches every page and sort).
- **Errors** reaching components are always `ApiRequestError` (`services/apiClient.ts`), whatever the generated
  error types say; narrow with `instanceof` or use `getErrorMessage()`.
- **Icons:** add an SVG to `src/assets/icons/` and export it from `components/shared/Icons` with `createIcon()`.
- **Dates:** the API speaks UTC ISO 8601; the UI shows and edits local time (`utils/dates.ts`).
- **Row keys:** time entries are keyed by `id` and `createdAt`, not `id` alone: the upstream can return two
  entries with the same id.
- **Page state in the URL:** a table's page, page size and sort live in the query string via `useUrlParams`
  (`read*Params` in `utils/urlParams.ts` validate them). Don't keep them in `useState`.
- **Desktop only:** layouts target desktop widths; no phone or tablet breakpoints.
- **Accessibility:** real `<button>`s for actions, labels on every input (ids from `useId()`), errors and hints
  tied to their field with `aria-describedby` (`describedBy()` from `FormField`), `aria-label` on icon-only
  buttons, dialogs via `SidePanel` / `ConfirmModal` (focus trap, Escape, focus returns). A failed save moves
  focus to the first invalid field.
- **Messages:** validation messages are full sentences (`Comment is required.`); every empty list shows `No data.`
- **Formatting:** Prettier (`.prettierrc`: double quotes, 80 columns). Run `npm run format` before committing;
  `src/generated` is ignored.

## Tests

`npm test -w frontend` runs Vitest on `src/**/*.test.ts` in a fixed timezone (`Europe/Sarajevo`, has summer time),
so date expectations hold on every machine. Unit tests cover the pure logic in `utils/` and `services/`; the API
itself is covered by the backend's end-to-end tests.
